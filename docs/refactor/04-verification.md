## 4. 分类结论

### 通过（自动化验证覆盖）
- DocumentWriteService 五种写入、CAS、幂等、两阶段账本与崩溃恢复；**所有写入来源**（编辑器、产物交付、章节提交 / 定稿 / 全自动定稿、去味替换、场景追加、提案接受、建书资料）都在同一账本留下 WriteReceipt（`doc_history` 可查）。
- 产物卡状态由服务端投影：保存 ≠ 确认、待审 ≠ 定稿、生成后原文被改 → 原文已变化、技能保存后被改 → 已失效、定稿措辞带记忆同步状态。
- 技能计划：本次 / 作品 / DeepWrite 来源、排除原因、冻结；**预览与执行同一 planHash**；子阶段（重写 / 去味 / 审稿）按各自任务解析并冻结。
- 审稿结论按被审文本 hash 入账；文本变化后显示「已失效」；作者可「审稿当前版本」。
- Agent 作用域与权限、运行状态机、重启对账、会话并发防护、切书隔离。
- 工具执行（设计文档的三个可选项）：只读结果缓存按作品状态戳失效（文件写入、可见性、技能、细纲确认各有断言），失败不缓存，副作用后清空；同轮重复调用只执行一次；连续只读调用并发执行且结果按原顺序回填；副作用调用单独顺序执行；运行指标（首字时间、模型 / 工具耗时、缓存命中、重试、用量来源）落库并随回执、`run_status` 返回（`tool_exec_tests.rs`、`agent_loop_tests.rs` 两个多调用轮次测试、前端指标测试）。
- 从干净副本按锁文件可复现构建与测试。

### 部分
- **只读并发的实际收益**：并发执行已实现并测试了正确性（顺序、去重、隔离）；数据库查询仍经单连接锁串行，只有文件读取能重叠，没有测量真实书稿规模下的提速。
- **可访问性**：键盘、焦点、ARIA、对比度（逐对计算 ≥ 4.5:1）已做；屏幕阅读器未实测。
- **阻塞文件 IO 仍在 tokio 工作线程执行**：实测定稿服务端 56–91 ms、界面完成 242 ms（mock 环境），未观察到饿死；没有改动 IO 模型（改动面大、收益未经测量证明）。
- **版本快照无自动清理**：刻意不自动删除历史（删除即可能丢稿）；数量随写入增长，需维护者确定保留策略后再做。
- **多文件「部分成功」**：服务端逐项状态有单元测试；浏览器中只能经旧会话的建书卡触发，未做端到端。

### 未验证
- **真实模型端到端**（工具调用兼容性、流式中断、真实 usage、输出质量）。
- **中文输入法（IME）手动测试**：编辑器与输入框有 `compositionstart/end` 保护，但未人工验证。
- Edge 以外浏览器；百万字级长文性能；生产数据影子演练。
- 长流式输出的渲染开销：消息项已 `memo`、运行卡只重渲染自身，但没有做逐 token 渲染次数 / 帧耗时的测量。

### 阻塞
- **旧界面从源码构建**：仓库只有编译产物，回退只能复用已发布的静态树。
- **真实模型验证**：需维护者批准渠道与费用（06-operations §6）。
