短篇全书节奏蓝图（8~15节·付费墙卡点）

## 提示词模板

【全书蓝图·官方默认】为一篇短篇（8000~2 万字）一次性规划全书的「节奏蓝图」。**只输出一个 JSON 对象**。
**核心原则：先把整篇的核心冲突与走向和用户对齐，别自己闷头生成。**
- **默认先追问对齐**：先返回 { "ask": "整篇当前目标 + 已知前提 + 这次需要作者决定什么", "options": ["方向1","方向2","方向3"] }（3~5 个具体、互斥、可直接作为生成依据的候选，围绕核心冲突 / 结局反转取向 / 情绪基调 / 一句话高概念）；禁止只问「你想怎么走」；一次只问一个最关键的，最多 1~2 轮。**追问也必须是这个 JSON**：候选放进 options 数组，绝不把问题和选项写成 1. 2. 3. 的正文列表。
- **仅当用户这条消息已明确给出整篇方向**（核心冲突 / 结局取向等关键走向），才跳过追问、直接产蓝图。
对齐后返回全书蓝图 JSON：
{
"blueprint": {
"concept": "一句话高概念——这篇最反常识的点（标题级钩子）",
"infoGap": "信息差图：谁知道什么 / 谁不知道 / 读者比哪个角色多知道什么，一段话",
"engine": "叙事发动机：双重身份 | 误会链 | 救赎互补 | 其它一句话",
"closingLoop": "首尾闭环物或台词——开篇埋下、结尾回收它的完整含义",
"maleViewAt": 4,
"fakePayoffAt": 7,
"paywall": 3,
"sections": [
{ "n": 1, "event": "一句话事件", "mood": "压 | 暖 | 笑 | 甜 | 危 之一", "hook": "节末钩子", "plant": "本节埋的伏笔（无则空串）", "payoff": "本节回收的伏笔（无则空串）" }
],
"finale": { "reversal": "终极反转是什么", "ending": "结局暴击落点" }
}
}
硬要求：
- **节数**：8~22 节——都市情感 / 轻喜 12~14 节为宜，古言 / 强情节 15~22 节；`n` 从 1 开始连续编号。
- **付费墙**：`paywall` 只能取 3 或 4——全文最强悬念卡在该节末尾。
- **三幕落位**：开篇暴击落在第 1~2 节（约占全文 15~20%）；冲突升级段约占 60%；
终极反转所在节号 ≥ 全文 70% 处；最后一节必须兑现结局锚点。
- **对方视角奖励**：`maleViewAt` 落在全文 20%~35% 处——向读者明示他的真心 / 隐情的一半，
把「他爱不爱」的悬念换成「何时说清」的期待；只揭一半，最关键一层留到最后。
- **阶段性兑现**：`fakePayoffAt` 在付费墙之后、结局之前——一次假掉马 / 部分兑现，留一个未解的定义问题。
- **情绪循环**：`mood` 同一标签不得连续超过 2 节（苦不积压、甜不齁腻）。
- **伏笔链**：`plant` / `payoff` 合计至少覆盖 3 节；终局证据必须在前面节里埋过，严禁结局发明证据。
- **每节必变**：event 必须含一个变化（新信息 / 关系位移 / 危机 / 反转 / 回收），不许纯聊天纯回忆；
每节必须有 hook；单一主线，出场人物 ≤ 5 个。
- 每个字段都是**简短要点**，绝不写成叙事、对白或正文。
- **只返回这个 JSON 对象本身**，前后不要任何其它内容。
